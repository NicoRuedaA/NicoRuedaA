Manager of Legends

manageroflegends.com ↗(nueva pestaña)(new tab) Código privadoPrivate code

Un Football Manager para equipos de MOBA, que se juega en el navegador.A Football Manager for MOBA teams, played in the browser.

Ligas, fichajes, draft y partidas simuladas en directo. Todo el juego vive en un motor en Rust compilado a WebAssembly; la interfaz en React solo dibuja lo que el motor decide.Leagues, transfers, drafts and matches simulated live. The whole game lives in a Rust engine compiled to WebAssembly; the React interface only draws what the engine decides.

Debajo hay más sistemas: A* en 8 direcciones sobre una rejilla de 196×196, simulación en directo en un Web Worker con paso fijo de 0,05 s, una IA de draft que puntúa counters y sinergias y un parche de equilibrio cada 14 días (4 campeones mejorados y 4 empeorados).Other systems underneath: 8-direction A* on a 196×196 grid, a live simulation in a Web Worker at a fixed 0.05 s step, a draft AI that scores counters and synergies, and a balance patch every 14 days (4 champions buffed and 4 nerfed).

ProblemaProblem

Al principio, ojear a un rival devolvía un número con ruido aleatorio y sin semilla. Al recargar la partida, el mismo ojeador daba otro número. Y un número se lee como un hecho aunque sea una suposición.At first, scouting a rival returned a number with unseeded random noise. Reloading the save made the same scout report a different number. And a number reads as a fact even when it is a guess.

DecisiónDecision

Cambié el número por una banda (FIG. 1). La calidad del ojeador marca desde dónde empieza y hasta dónde puede cerrarla: un mal ojeador nunca llega a la certeza, por mucho tiempo que mire.I replaced the number with a band (FIG. 1). The scout's quality sets where it starts and how far it can close: a poor scout never reaches certainty, however long they watch.

ResultadoResult

Con ±18, las bandas de un jugador de 60 y de uno de 90 se solapan, así que no se puede fichar a ciegas: hay que mandar a un ojeador.At ±18 the bands of a 60-rated and a 90-rated player overlap, so you cannot sign players blind: you have to send a scout.

Porté a Rust Shotcaller, un MOBA hecho en Godot por el equipo Spicy Lobster y publicado con licencia no comercial, y lo convertí en un simulador de entrenador. Tú das órdenes de macro; un rival controlado por IA juega con la misma información que tú.I ported Shotcaller, a MOBA made in Godot by the Spicy Lobster team and published under a non-commercial licence, to Rust and turned it into a coach simulator. You give macro orders; an AI rival plays with the same information you have.

ProblemaProblem

El original, en GDScript, se apoyaba en corrutinas de Godot y en llamadas aleatorias repartidas por varios scripts, así que una partida no se podía reproducir tick a tick.The original GDScript relied on Godot coroutines and random calls spread across several scripts, so a match could not be replayed tick by tick.

DecisiónDecision

Un tick fijo de 30 Hz con un orden de fases estricto (entradas, plan GOAP, cola de eventos, movimiento, colisión, impacto, resolución), una sola RNG con semilla, un planificador GOAP con profundidad máxima 32 y búsqueda de caminos JPS con desempates estables. El rival solo ve lo que ve su equipo.A fixed 30 Hz tick with a strict phase order (inputs, GOAP plan, event queue, move, collide, hit, resolve), a single seeded RNG, a GOAP planner bounded at depth 32 and JPS pathfinding with stable tie-breaking. The rival only sees what its team sees.

ResultadoResult

Misma semilla, misma partida. 206 commits míos en unas cuatro semanas, 513 tests en Rust, órdenes tipadas con ciclo de vida propio y un HUD de entrenador en React y Three.js.Same seed, same match. 206 of my commits in about four weeks, 513 Rust tests, typed orders with their own lifecycle and a coach HUD in React and Three.js.

Sueltas un sprite de pixel art y sale un modelo 3D de vóxeles optimizado.Drop in a pixel-art sprite and get an optimised 3D voxel model.

Una herramienta sin instalación para quien hace juegos: exporta a MagicaVoxel, Blender o cualquier motor. Sin IA generativa, solo geometría determinista.A no-install tool for people who make games: it exports to MagicaVoxel, Blender or any engine. No generative AI, just deterministic geometry.

ProblemaProblem

Pasar pixel art a 3D a mano es lento, y las herramientas con IA inventan volumen y no respetan los píxeles.Turning pixel art into 3D by hand is slow, and AI tools invent volume and ignore the pixels.

DecisiónDecision

Todo es matemática: transformada de distancia de Felzenszwalb–Huttenlocher para el volumen, casco visual cuando hay vistas laterales, greedy meshing para fusionar caras y oclusión ambiental por esquina. Lo pesado va en Web Workers.It is all maths: a Felzenszwalb–Huttenlocher distance transform for volume, a visual hull when side views exist, greedy meshing to merge faces and per-corner ambient occlusion. The heavy work runs in Web Workers.

ResultadoResult

Exporta VOX, OBJ, GLB y FBX, con CI en GitHub Actions. Un colaborador externo añadió niveles de detalle en un PR que revisé y fusioné. Empezó como un script en Python (sprite2voxel.py) para el Tactical Prototype.It exports VOX, OBJ, GLB and FBX, with CI on GitHub Actions. An outside contributor added levels of detail in a PR that I reviewed and merged. It started as a Python script (sprite2voxel.py) for the Tactical Prototype.

lo que aún no hacewhat it doesn't do yetCon sprites reales llenos de accesorios finos (bastones, espadas) la reconstrucción aún no es del todo predecible; el mapa de confianza y la separación del código están en el roadmap.With real sprites full of thin props (staffs, swords) reconstruction is not fully predictable yet; the confidence map and a code split are on the roadmap.

Sports Face

GitHub ↗(nueva pestaña)(new tab)

Un código de texto es una cara: siempre la misma, en 2D o en 3D.A text code is a face: always the same one, in 2D or in 3D.

Retratos procedurales para un juego de gestión deportiva: el mismo código dibuja siempre al mismo jugador, con renderizadores intercambiables en Canvas 2D, SVG y WebGL2.Procedural portraits for a sports-management game: the same code always draws the same player, with interchangeable Canvas 2D, SVG and WebGL2 renderers.

ProblemaProblem

Un juego de gestión necesita miles de caras distintas y estables: un jugador tiene que ser reconocible temporada tras temporada, también cuando envejece.A management game needs thousands of distinct, stable faces: a player must stay recognisable season after season, including as they age.

DecisiónDecision

Identidad y apariencia empaquetadas en campos de bits (FaceDNA) con un código portable y suma de verificación. Un enrutador elige entre Canvas 2D, SVG toon, dos laboratorios de morphing y un renderizador WebGL2.Identity and appearance packed into bit fields (FaceDNA) with a portable code and a checksum. A router picks between Canvas 2D, SVG toon, two morph labs and a WebGL2 renderer.

ResultadoResult

100 identidades congeladas como línea base visual, un renderizador WebGL2 escrito desde cero con su propio lector GLB y un pipeline offline en Python que reduce 200 cabezas a 16 morph targets con PCA (95,26 % de la varianza).100 identities frozen as a visual baseline, a WebGL2 renderer written from scratch with its own GLB parser, and an offline Python pipeline that reduces 200 heads to 16 morph targets with PCA (95.26% of the variance).

lo que aún no hacewhat it doesn't do yetEs un prototipo técnico, no un producto. El estilo toon parte de ToonHead (Johan Melin, CC BY 4.0) y la cabeza 3D base (GNM, de Google) solo admite uso no comercial.It is a technical prototype, not a product. The toon style builds on ToonHead (Johan Melin, CC BY 4.0) and the base 3D head (Google's GNM) is non-commercial only.
